Jeffrey Traces Release

Version 0.13.0 · September 2026

The profiler and the tracer now share one file. Jeffrey Traces records span trees as JFR events inside the same flight recording as your CPU samples, SQL statements, lock waits and GC pauses — so “this span took 400 ms” and “doing what?” are answered by the same artifact. No collector to deploy, no exporter to configure, no sampling decision made for you at the edge.

Release Notes

New
Feature 01

Jeffrey Traces Ready to use

One unit of work — an HTTP request, a gRPC call, a batch job — becomes a tree of timed spans, and that tree is correlated with everything else the JVM was doing at the same time. A tracing tool normally tells you a span took 400 ms and stops there; the next question needs a profiler and a second, correlated data source. Jeffrey has both in one file — and keeps no list of span event types: any JFR event declaring a spanId field participates, custom and third-party events included, with zero configuration.

The waterfall splits self versus child time, dims everything off the critical path, folds repeated siblings into runs with P95 and mini-histograms, overlays GC pauses, safepoints, blocking spans, exceptions and notifications — and the Why slow panel plus per-span flamegraphs answer doing what, correlated purely by thread and time window.

Feature 02

From Zero to Traced in One Dependency

The jeffrey-tracing libraries meet your code where it is. The Spring Boot starter auto-configures root spans for HTTP, statements for JDBC and MyBatis, pool events for HikariCP and interceptors for gRPC — add the dependency and write nothing.

Underneath sits a zero-dependency Tracer API of eleven methods — run, call, stamp, fork, continueIn and friends — with context in a ScopedValue bounded by a lambda so it cannot leak. And for the methods in between, @Traced plus the Jeffrey Agent weaves the span at class load: the method is left exactly as it was written, argument capture is opt-in and allow-listed.

The agent argument string is the entire configuration — no system properties, no config files.

Feature 03

Ask Questions Across Every Trace

Span attributes, the source event’s own fields and the span shape are flattened once into a searchable index, and four pages read it: Traces by Operation groups work by endpoint with percentiles; Search Traces ANDs attribute conditions with same-span or anywhere-in-trace matching; Attribute Values ranks every value of a key by total time; Latency by Attributes draws each value over log-spaced duration buckets.

Percentiles hide bimodality — the heatmap shows it. And a search result doesn’t open a flat list: it opens the waterfall in place.

Improvements

Microscope

Notifications & Exceptions in Traces

A new jeffrey.Notification event lets the application write a moment — a threshold crossed, a circuit breaker opened — into its own recording, stamped with the enclosing span’s ids so it lands in the right place in the waterfall. Exceptions need no instrumentation at all: every throw is attributed to the span that was running.

Profile Databases, Dramatically Smaller

The same SQL text used to be stored per-row four times over — a 92 MB recording could produce a multi-gigabyte profile database. Repeated texts are now dictionary-pooled and events became a view, so every existing reader is unaffected while the database shrinks by orders of magnitude.

Trace Export for AI Assistants

The waterfall and the operation drill-down export what you are looking at as a single Markdown document built for pasting into an AI assistant — opening with a how-to-read preamble so span semantics aren’t guessed wrong.

Flamegraphs Fail Loudly

A failed flamegraph request now surfaces the error instead of spinning forever — and the weight extractor skips events that carry no class instead of producing a broken entity.

Hub & Provisioner

A Provisioned JVM Records What Traces Need

The stock JFR configuration keeps lock waits above 20 ms and socket I/O above 1 ms — coarser than a trace is read at. The provisioner now starts a second recording carrying only the lowered thresholds; JFR applies the most verbose setting, so the dumped files and the live stream both pick them up. TRACING=off opts out.

Environment Variables as a Real Config Layer

The provisioner merges the environment as a proper configuration layer instead of per-field fallbacks — and a settings-file ordering bug that could fail provisioning outright on real installs is fixed.

Platform

MyBatis Tracing by Default

Statements are named by their mapper method — far more readable than raw SQL — and record the bound parameter values. The interceptor takes over from the generic DataSource wrapper so nothing is double-recorded.

Jeffrey Tracing Documentation

Tracing is a first-class product on the docs site: 18 guide pages plus one page per Tracer API method, with the Jeffrey Events catalog and span trees drawn as real diagrams.

Claude Skills in the Box

Five skills ship with the libraries so an AI assistant can instrument a codebase correctly — core, gRPC, HTTP client, MyBatis and Spring REST server.

Streamed JDBC Row Counts

Streamed statements now report how many rows they actually delivered, so a query that returns nothing is distinguishable from one that floods.
