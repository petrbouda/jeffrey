0.13.0 “Jeffrey Traces” — five mockups

Five directions for the 0.13.0 release-notes page. All of them keep the production skeleton from ReleaseNotesView.vue — hero banner with a per-release color identity, the 5-stat strip, the sticky version switcher, numbered feature sections with galleries, and the product-grouped Improvements grid — so whichever wins ports directly into the component the way .hero-banner-120 / .feature-frame-120 did for 0.12.0. Gallery visuals are styled placeholders; they mark exactly where the real v0.13.0 screenshots go (public/images/release-notes/v0.13.0/…).

1

Waterfall teal → sky recommended

The closest sibling to 0.12.0's structure: version card, three features (Traces · Instrumentation · Analytics), Notifications folded into the Improvements grid. A trace-bar color identity — deep navy hero, teal-to-indigo animated frame. Lowest-risk port.
2

Deep Trace indigo → emerald · 4 features

Hero artwork — a mini waterfall drawn in the 0.7.0-style image box — and four full features: Notifications & Exceptions get promoted from an improvement tile to Feature 04 with their own docked-panel visual. The most complete telling of the tracing story.
3

One Recording amber → teal · full-width waterfall

Narrative-led: the hero and the stats strip sell the zero-infrastructure angle (“1 recording · 0 collectors”), and Feature 01 stacks its text above a full-width waterfall so the flagship visual gets the whole row. Features lean on Traces by Operation as the analytics entry point.
4

Terminal magenta → violet · code-first

A @Traced code card replaces the version card in the hero, and the feature order is developer-first: instrumentation (with all 11 Tracer API methods) leads, the waterfall follows. Aimed at the reader who asks “what do I have to write?” before “what do I get?”.
5

Spectrum one hue per feature

The most visually adventurous: four features each on their own tinted band (teal, violet, amber, rose), multi-hue stats, and a dark “By the numbers” band before the Improvements. New CSS surface, but every pattern still derives from the production page.

Shared across all five (from the codebase, not invented)

  • Headline: Jeffrey Traces — spans recorded as JFR events in the same recording as the profiler's samples; waterfall with critical path, folded sibling runs, GC/safepoint/blocking/ exception/notification overlays, “Why slow” panel, per-span flamegraphs.
  • Instrumentation: the jeffrey-tracing libraries (9 modules), the 11-method Tracer API, @Traced + agent weaving with allow-listed argument capture.
  • Analytics: Traces by Operation, Search Traces, Attribute Values, Latency by Attributes.
  • Improvements pool (10): notifications & exceptions (a feature in mockups 2/5), dictionary-pooled profile databases, trace Markdown export for AI, flamegraph error surfacing, instance-timeline card cleanup, provisioner tracing thresholds, provisioner env-var config layer + ordering fix, MyBatis tracing by default, the standalone Tracing docs product, Claude Skills, streamed JDBC row counts.
  • To implement the winner: add .hero-banner-130 + .feature-frame-130 styles, the v130*Images galleries and activeImages keys, the select option, and the 0.13.0 <template> block to ReleaseNotesView.vue; drop screenshots under public/images/release-notes/v0.13.0/.
