Release Notes

Jeffrey Traces Release

Version 0.13.0 · September 2026

A tracing tool normally tells you that a span took 400 ms and stops there. The next question — doing what? — needs a profiler and a second, correlated data source. Jeffrey has both in one file. Spans are JFR events in the same recording as the profiler’s samples: a waterfall with GC, safepoint and blocking overlays, application-written notifications, zero-config exceptions, and a flamegraph behind every span.

New
Feature 01

The Trace Waterfall Ready to use

One unit of work — an HTTP request, a gRPC call, a batch job — becomes a tree of timed spans, correlated with everything else the JVM was doing at the same time: CPU samples, SQL statements, socket reads, lock waits, GC pauses and safepoints.

Every bar splits self versus child time, everything off the critical path is dimmed, and repeated siblings fold into a run with count, total, median, P95 and a mini-histogram. Toolbar overlays add GC pauses and safepoints as lanes, promote blocking leaf spans — lock, park, sleep, allocation stall, virtual-thread pinning — and jump straight to the first error.

The Why slow panel ranks GC, safepoints, I/O, locks and the remainder for any span, each linking to the profile view that explains it — and every span opens a flamegraph, Inclusive or Self, correlated purely by thread and time window.

Feature 02

Instrumentation That Meets You Where You Are

The jeffrey-tracing libraries instrument without rewriting code. The core Tracer API — eleven methods, from run and call to fork and continueIn — has zero dependencies; around it sit modules for Servlet, Spring, JDBC, HikariCP, MyBatis and gRPC, and a Spring Boot starter that auto-configures the lot.

Or skip the API entirely: mark a method @Traced and the Jeffrey Agent weaves the span at class load — the method is left exactly as it was written, nests under whatever span is in progress, and is marked failed on throw. Argument capture is opt-in by parameter name and restricted to an allow-list of stable value types.

Feature 03

Trace Analytics

Span attributes, the source event’s own fields and the span shape are flattened once into a searchable index — three new pages read it.

Search Traces ANDs conditions — equality, numeric comparison, presence — with same-span or anywhere-in-trace matching, and compares the matches’ latency against the whole profile. Attribute Values breaks one key into every value it took, ranked by total time rather than call count. Latency by Attributes draws each value’s traces over log-spaced duration buckets: percentiles hide bimodality; the heatmap shows it.

Notifications are searchable exactly the same way — a kind, a message and attributes are just another row in the index.

Feature 04

Notifications & Exceptions

A trace shows what the runtime did; jeffrey.Notification lets the application add its own side of the story. A notification is a moment, not an interval — a threshold crossed, a cache warmed, a circuit breaker opened — written into the recording and stamped with the enclosing span’s ids, so it lands in the right place in the waterfall.

Kind and message stay low-cardinality by design and are dictionary-pooled; per-occurrence detail goes into searchable attributes.

Exceptions need no instrumentation at all: every thrown exception in the recording is attributed to the span that was running, with the stack trace folded into the same docked panel notifications use.

Improvements

Microscope

Profile Databases, Dramatically Smaller

The same SQL text used to be stored per-row four times over — a 92 MB recording could produce a multi-gigabyte profile database. Repeated texts are now dictionary-pooled and events became a view, so every existing reader is unaffected while the database shrinks by orders of magnitude.

Trace Export for AI Assistants

The waterfall and the operation drill-down export what you are looking at as a single Markdown document built for pasting into an AI assistant — opening with a how-to-read preamble so span semantics aren’t guessed wrong.

Flamegraphs Fail Loudly

A failed flamegraph request now surfaces the error instead of spinning forever — and the weight extractor skips events that carry no class instead of producing a broken entity.

Instance Timeline, Tidier

The per-instance timeline card folds its meta strip into the card header — the same information, one visual unit per instance.

Hub & Provisioner

A Provisioned JVM Records What Traces Need

The stock JFR configuration keeps lock waits above 20 ms and socket I/O above 1 ms — coarser than a trace is read at. The provisioner now starts a second recording carrying only the lowered thresholds; JFR applies the most verbose setting, so the dumped files and the live stream both pick them up. TRACING=off opts out.

Environment Variables as a Real Config Layer

The provisioner merges the environment as a proper configuration layer instead of per-field fallbacks — and a settings-file ordering bug that could fail provisioning outright on real installs is fixed.

Platform

MyBatis Tracing by Default

Statements are named by their mapper method — far more readable than raw SQL — and record the bound parameter values. The interceptor takes over from the generic DataSource wrapper so nothing is double-recorded.

Jeffrey Tracing Documentation

Tracing is a first-class product on the docs site: 18 guide pages plus one page per Tracer API method, with the Jeffrey Events catalog and span trees drawn as real diagrams.

Claude Skills in the Box

Five skills ship with the libraries so an AI assistant can instrument a codebase correctly — core, gRPC, HTTP client, MyBatis and Spring REST server.

Streamed JDBC Row Counts

Streamed statements now report how many rows they actually delivered, so a query that returns nothing is distinguishable from one that floods.
