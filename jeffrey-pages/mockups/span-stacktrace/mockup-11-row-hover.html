Throw row hover

The first row of each panel is drawn hovered, at the width a real trace modal gives this region. The chips above each panel are the ledger: what boxes that variant still needs, and what it deletes. The hover and the padding are one question, not two — the head’s negative-margin pair exists only to be filled, so a treatment that does not fill it does not need it.

0 Todaythe problem

Two nested negative-margin pairs. The row already had one; I added a second on the head purely so the hover would have something to fill. That is the whole reason it exists — and it is why the fill runs the panel width: measured here, the highlight is 1886px wide while the ink ends at 238px, so 87% of it is empty. The tint is --color-primary-light as well, where the app hovers rows with --color-bg-hover in both TraceCardList and TraceOperationSummary.

5 Both boxes gonemost removed

Every padding and margin deleted from both. Rows sit inside the region body’s own padding and separate with their border alone; nothing overhangs anything. The trade is visible in the drawing: the separators no longer reach across the region, so the list reads as narrower than the panel holding it — and .sd-entry is shared with notification rows, so this restyles those too. So: can the padding and margin go?

The head’s pair, yes — entirely, in every variant. It only ever existed to give the hover a box, and the row underneath already had one. That is a straight deletion with nothing to weigh: variants 1–5 all drop it.

The row’s pair is a different question, because it predates this work and is shared with notification rows. Variant 5 shows what removing it looks like: tidier CSS, and a list that no longer spans its own region. Worth doing only if you like that reading better — it is a visual change, not a cleanup.

1 is the recommendation: the head’s box deleted, the hover moved onto the box that was already there, and the app’s own row-hover token instead of a lavender the app does not use for rows. 4 is the answer if you want no box to exist anywhere — nothing is filled, so nothing needs one.
