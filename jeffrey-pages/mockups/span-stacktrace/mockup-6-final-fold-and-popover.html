One fold rule, learned once

A run of consecutive frames the profile does not consider application code collapses into one bar. The classification is not new — StacktraceTypeResolver and LambdaMatchUtils already decide this for flamegraphs, so a frame folds here exactly when it is dimmed there.

Because the rule is the same in the popover and in the span, the reader learns it once and it holds everywhere a stack appears. Nothing is ever dropped: every folded frame is one click from view, and Fold libraries turns the whole thing off.

The case that has to be handled

A throw from inside a library has no application frames at all, and the rule as stated would fold it down to nothing — which reads as a broken panel, not as an answer.

So the fold has a floor: when folding would leave nothing standing, it does not run. The stack renders raw, with the top frames shown as they are. Better a long honest stack than a short empty one, and this is the case worth writing a test for first.

What it buys

Two reads, one mental model. Hover for the answer, open the span for the whole thing, and the stack looks the same in both. No modal on a modal, no split column fighting the event-fields table — the trace stays on screen the entire time.

It is also the smaller build: a popover that already exists gains content, and the region that already renders the row gains a fold. The fold classification is reused, not written.

What it costs

The fold is an opinion, and it is now in two places. Getting the rule wrong is twice as visible, and the popover has room for so few lines that a bad classification wastes the preview entirely — so the library-only floor on the right is not an edge case to defer.

There is still no home for copy-as-text. Direction 4 had room for it and this does not, so either the chip goes in the stack header and the text is the 45-frame raw stack, or it waits.
