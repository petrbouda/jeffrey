Instance Timeline — ten directions

The Instance Timeline is the page you land on for every hub-connected project, and it is the one time view in Jeffrey that does not speak the app's own language. Its axis runs right to left; every card carries its own copy of the ruler, so no two instances can be compared; a row costs ~140px to draw one bar; and an instance outside the selected window renders a full-height empty card with nothing saying why. Meanwhile the Trace detail modal — waterfall rows on one shared grid, a brush minimap, lanes, pins, total-vs-self bars — already solves all of this, three screens away.

Ten directions below, each drawing the same project so what differs is layout, never data. The three instances from the screenshot (25pjc, qb9g7, s88hb) are the ones inside the 24-hour window; the directions that only pay off at scale widen to the same project's full 7- or 30-day history, where the other nine instances live. Every page reuses the shipped .wf-* grid and the real design tokens, so nothing here is a look that the app cannot actually produce. The session drawer stays exactly as it is in all ten — only the route to it changes.

What the data actually says

  • The three real instances form a rolling restart chain: s88hb stops 05:43:44, qb9g7 starts 05:43:47 — 3 seconds later; qb9g7 stops 09:39:03, 25pjc starts 09:39:07 — 4 seconds later.
  • So this project has run exactly one instance at a time, with two sub-5-second holes in coverage. The current page cannot show either fact, because its cards have no shared axis.
  • The pod names carry the replicaset: 86dd87c8ff → 74bd9b8c8d is a deploy at 2026-08-24 05:43:47, and it is derivable today with no backend change.
  • expiringAt and expiredAt are on ProjectInstance and rendered nowhere. jdk.Shutdown is fetched for the drawer and shown only as raw fields.

Tokens these directions would need

Everything else is copied verbatim from design-tokens.css into tokens.css. Only two things are proposed, and only two directions need them:

TokenValueUsed byWhy not an existing one
--deploy-mark#7780bf4, 5, 10 = --color-secondary. Deliberately not primary/danger/warning — each already means selection, crash and critical path in the same picture.
--coverage-0…4#f1f5f9 → #00d27a9 A five-step ramp on the success hue. No sequential ramp exists in the token file; the chart series palette is categorical, not ordered.

Two colours in the shipped component have also drifted off-token and are corrected everywhere here: rgba(16,185,129,…) is #10b981 but --color-success is #00d27a, and rgba(156,163,175,…) is #9ca3af against --color-text-light #b6c1d2 — so the card washes never matched the accent borders beside them.

Each direction ends with a what it buys / what it costs / what it takes to build block, including the cases where a direction genuinely does not earn its space. Several combine cleanly — 1 or 2 is the base, and 3, 4, 5, 6 and 9 are overlays on top of it rather than alternatives to it.
