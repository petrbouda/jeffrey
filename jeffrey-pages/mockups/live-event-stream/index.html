Microscope — live event stream mockups

Five design directions for the workspace Event Log now that it streams live over SSE and carries file events. Each mockup shows the same eight events — recording chunks, artifacts, session and instance lifecycle — so the layouts can be compared directly, starting from the current design as a baseline.

Current — as shipped baseline

The flat event list on master today, styles copied verbatim from the component. This is what the five alternatives are competing against.

Timeline rail

Vertical rail with a colour-coded node per event type. Arriving events slide in with a green halo.

Dark, dense tail -f view. Fixed columns, one line per event, throughput and resume offset in the status bar.

Session cards

File events accumulate as chips on the session they belong to. Shows the chunk still being written as a dashed placeholder.
4

Split feed + detail

Master-detail — compact feed left, full event payload right, so inspecting an event needs no modal.
5

Stats + ticker

KPI strip above a ticker feed. Deliberately shows the reconnecting state and its resume offset.

What the backend actually provides

  • Four new event types: recording file, artifact file, instance finished, instance expired.
  • The chunk currently being written is never announced — mockup 3 is the only one that visualises it.
  • Every batch carries a lastOffset; a reconnect resumes from it, so nothing is missed or shown twice.
  • File size is a first-sighting value — later compression does not emit a new event.
  • Connection state is already modelled as Live / Reconnecting / Paused.
