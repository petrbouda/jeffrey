What it buys

  • The one direction where a notification never loses its span: it is drawn on the bar that emitted it.
  • Two readings from one picture — where in the trace a notification landed, and how many each span carries, before anything is opened.
  • The detail panel already has a region grammar (Attributes, Event fields). Notifications is a third region, not a new surface.
  • Nothing overlays anything: no popover, no second pane, no extra Escape level.

What it costs

  • A pin needs a bar to sit on. A 2 ms span is drawn at the 0.4% floor width — three pins on it are one smudge.
  • Fold a subtree and its notifications fold with it. A CRITICAL alert can hide three folds deep, the way an error already can.
  • Reading a notification costs two clicks: select the span, then read the region.
  • The bars are already carrying self/children shading, the critical-path border and the pause wash. Pins are a fourth layer on the same 0.8rem.

What it takes to build

  • Pins go in the existing .wf-track beside .wf-bar; the count badge in .wf-name beside the error badge.
  • One new region in TraceSpanInlineDetail.vue, following the .sd-region pattern the file already has twice.
  • Needs notifications keyed by span id — Record<spanId, TraceNotificationRow[]>, the shape TraceContext.spanWaits already uses.
