How it works

From "why is it slow?" to a verified fix —
without leaving the terminal.

The Microscope plugin gives your agent skills that know how to read JVM evidence, and an MCP server that hands it the numbers. The profile and the source code end up in front of the same reader.

Record

Profile a benchmark, a test or the app itself with JFR or async-profiler.

profile-run

Analyze

CPU, wall-clock, allocation, locks, GC, JIT, heap — the agent reads the flamegraph, not a screenshot.

analyze-jfr analyze-heap

Change

Hot frames are mapped to real source lines and turned into minimal, behaviour-preserving edits.

advise-jfr

Prove

Both revisions profiled the same way, weighed with differential flamegraphs.

regression-check

Already running Microscope?
The MCP server is already on.

It answers at /api/mcp on the port you reach Jeffrey on. Install the plugin to get the skills and agents on top.

# on the v2 MCP runtime
/plugin marketplace add petrbouda/jeffrey
/plugin install microscope@jeffrey
Where v2 is not the default, start with MCP_SDK_GENERATION=v2 claude.
# ~/.codex/config.toml → [features] mcp_2026_07_28 = true
codex plugin marketplace add petrbouda/jeffrey
Codex v0.147.0 or later, then /plugins.
gemini extensions install ./jeffrey/jeffrey-claude-plugin
Installs today; connects once Gemini CLI speaks MCP 2026-07-28.

Also a great UI for humans

Everything the agent sees, you can see too.

Microscope runs on your laptop as a JAR or a container. Drop in a JFR file, a heap dump, pprof or OTLP — open the same profile your agent is reading.

Flamegraphs that render fast

For every JFR event that carries a stack trace — CPU, wall-clock, allocation, locks, native memory.

Differential flamegraphs

Before vs. after, branch vs. main. See exactly which frames grew and which shrank.

Sub-second timelines

Zoom into the millisecond your service stalled and pull a flamegraph for just that window.

Heap dump analysis

Dominator trees, leak suspects, class-loader leaks, OQL and SQL over the heap index.

JVM dashboards

GC, safepoints, JIT, threads, native memory, container limits and configuration.

Auto Analysis

Rules that flag the usual suspects before you — or your agent — start digging.

Read-only by declaration

100 of 111 tools only read, and every tool says so in its MCP annotations. The eleven that write declare it.

Your data stays local

Jeffrey never calls a model provider. The only AI is the agent you already run, calling in.

Switches for reaching out

Hub and IDE tool families each have their own off-switch in configuration.
